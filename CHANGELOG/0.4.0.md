# 0.4.0

Alignment with the restructured metadata API, including:
- New processing configurations - whereby each dataset defines a "plan" of data processing configurations to execute in
a specific order, rather than assumptions being made in the processing pipeline
- Flag definitions are now held in the metadata, rather than being hard-coded in the processor
- Time-anchor semantics are now available from the metadata and being used in the `TimeFrame` initialisations

This release also adds MAD despiking for flux variables.

### Breaking changes

- **Hard-coded flag names removed.** Flag systems and flag columns are no longer defined in the processor.
  A dataset's flagging comes entirely from its metadata; a dataset that defines no flagging gets no flag columns.
- **Metadata API format changes.** Pydantic models and domain models updated to fit the new metadata structure.

### New features

- **`LOAD` operation**: loading data into a container is now a plan step (`ConfigurationType.LOAD`,
  `LoadPipeline`) rather than a fixed stage. A plan can request loads at any point and more than once.
- **Flags from metadata** (FPM-1060): `ensure_flag_column` registers a dataset's flag systems and creates
  its core and QC flag columns from metadata, leaving existing flag columns untouched so their values are
  preserved.
- **Time anchor support** (FPM-1110): `TimeFrame`s carry a time anchor that now comes from dataset metadata.
  `map_time_anchor` maps the metadata semantics to the time-stream `TimeAnchor`, and merging now requires all
  inputs to share the same anchor.
- **Flux MAD despiking** (FPM-1034): `flux_despike.py` adds sliding-window median-absolute-deviation spike
  detection for the `H` and `Tau` flux variables, treating daytime and nighttime separately using solar
  radiation as the discriminator.
- **Method config injection moved into operations** (FPM-1077): each operation reads its own method
  configuration instead of the pipeline injecting parameters, simplifying `OperationPipeline`.
- **QC data removal** is deferred to after the end of each block of quality-control operations, so flags from all
  QC steps accumulate before any data is nulled.
