# 0.9.0

Methods now get their input datasets by name, taken from the new dataset metadata, instead of through `dep_ts` and
using dataset specific column names. Most derivation calculations have moved out into the new `hydrometlib` package.

This release also fixes a bug where flag columns defined in a dataset's metadata were not being initialised in the
processed dataset.

### Breaking changes

- **Named method inputs**: a method configuration can now declare its input datasets by an input name. Each one is
  its own argument, with the input name as the parameter and exactly one dataset as the
  value. The pipeline puts each input's `TimeFrame` into `config.params` under that name.
- **Flag columns on every dataset**: every saved dataset now gets every flag column declared in its metadata,
  whichever steps its plan has. Previously only the core flag column and the flag column for
  the operation that ran were created.
- **Aggregation keeps all flag columns**: the aggregation result now keeps every flag column, not just the core flag
  column.
- **`EddyProRun` moved**: it now lives in `operations/eddypro/eddypro_run_method.py` rather than
  `operations/derivation/derivation_methods.py`.

### New features

- **`distance_to_level` derivation**: the new `DistanceToWaterLevel` method works out the water level from the distance
  measured by the sensor and the sensor height.
- **`latent_heat_to_et` derivation**: the new `LatentHeatFluxToEvapotranspiration` method works out evapotranspiration
  from latent heat flux (`le`) and air temperature (`ta`).

### Refactors

- **Shared method base classes**: all methods now come from `OperationMethod` (`operations/operation_method.py`).
  Corrections, QC, infilling and aggregation are `TransformMethod`s, run as `method.run(tf, config)`. Derivations are
  `GenerativeMethod`s, run as `method.run(config)`. See `docs/operations.md`.
- **Derivations use `hydrometlib`**: the calculations are now taken from `hydrometlib`, and each derivation method only
  maps its inputs onto the matching function.
- **QC alignment**: QC checks against another dataset now line their result up with the rows being flagged using the
  new `QcMethod.align_to`. `QCPipeline` no longer does this itself.
- **Corrections share one date-range helper**: `CorrectionMethod.apply_within_dates` applies a correction only to
  rows within the configured date range. Longwave correction no longer fails when the `lw_unc` input is the raw
  version of the dataset being corrected, as the two share a column name.
- Date filters in QC and corrections now use the type of the time column, so they work with whichever time type the
  data has.

### Dependencies

- `hydrometlib` is added as a dependency.
- `time-stream` updated from 2.0.0 to 2.1.1, and other locked dependencies updated.
