# 0.10.4

Flag column names now come from the dataset metadata, rather than being built from the data column name (e.g.
`<column>_CORE_FLAG`). Each flag column's role is taken from the `flagType` of its flag scheme. A dataset no longer
needs a core flag column.

`list-sites` has a new `--historic` option, to list every site a network has ever had.

### Main changes

- **Flag columns looked up by role**: each operation finds the flag column it writes, and the core flag column, by
  role (`FlagRole`: core, quality control, correction or infill) from `TimeSeriesContainer.flag_column_roles`.
- **`flag_names.py` removed**: `core_flag_column_name`, `qc_flag_column_name`, `corrs_flag_column_name` and
  `infill_flag_column_name` no longer exist.
- **`OperationPipeline.get_flag_column` takes no arguments**: subclasses set a `flag_role` class attribute instead of
  overriding it. `get_core_flag_column` is added alongside it.
- **Core flag functions take column names**: `update_corrections_core_flags`, `update_quality_control_core_flags` and
  `update_infill_core_flags` are now given the core flag column and the operation's flag column, and only update the
  dataset's own data column rather than looping over every data column.

### New features

- **`list-sites --historic`**: lists every site the network has ever had, open or closed, with no date check, e.g. to
  fan out `historic` mode runs. It can't be used together with `--lookback`, `--start-date` or `--end-date`. Without
  `--historic` or any date arguments, the default `P2D` lookback from today still applies.

### Bug fixes

- **No core flag column needed**: a dataset without a core flag column used to raise a `ValueError` when core flags
  were updated after corrections, QC or infilling. Operations now still write their own flag columns (e.g. QC still
  flags and removes data), but no core flags are set.
- **QC with no QC flag column**: `QCPipeline.remove_flagged_data` now logs a warning and leaves the data as it is,
  rather than failing on a missing column.
