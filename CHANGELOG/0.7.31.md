# 0.7.31

Fixes DuckDB query failing when the parquet files for a site do not all hold the same
columns across the date range being read. This is a temporary solution - see the note on performance below.

### Bug fixes

- **Parquet schema changes within a date range**: DuckDB takes the schema of the first parquet file in a glob and
  applies it to every other file it reads. This causes issues when a site's columns change partway through a date range,
  e.g. a new variable is added at a site.

  `query_by_date_range` now passes `union_by_name=true` to `read_parquet`, so DuckDB builds the schema from every
  matching file and fills in nulls where a file does not hold a column.

  This is a temporary solution. Matching columns by name means DuckDB has to read the schema of every file in the
  glob before it can start reading data, rather than binding once from the first file, which has performance
  implications. A longer term fix should keep a site's parquet schema consistent so the files can be read without
  unioning them by name.
- **DuckDB thread count**: connections are now created with `THREADS=64` to help mitigate the performance implications.
