# 0.7.0

Adds snow handling for the COSMOS cosmic-ray neutron sensor (CRNS) processing chain, along with new aggregation and
derivation methods. This gets us to a point where we can calculate Volumetric Water Content (VWC - soil moisture),
accounting for snow.

Fixes problems found while processing 1-minute data: aggregation buckets at the edges of a processing window were being
built from partial data, correction and quality-control dependencies were being applied by row position rather than by
time, and a re-run could silently replace a whole day of stored data.

Failures are now raised properly - a run that could not process a dataset, find any sites, or find a processing
plan now exits with an error rather than reporting success.

### New features

- **CRNS snow estimated counts**: `get_snow_estimated_counts` reconstructs CRNS counts as if there had been
  no snow, because lying snow suppresses the counts. During a snow event the estimate holds the count from just before
  the snow started, and rises if the measured counts rise. Follows Wallbank et al. (2021).
- **Volumetric water content with snow**: `calculate_vwc_with_snow` subclasses `calculate_vwc` and uses the
  estimated counts (`CTS_EST_CRNS`) in place of the measured counts wherever a snow estimate exists.
- **Rolling mean for counts**: `rolling_mean_for_counts` aggregation method gives each data point a mean
  taken from a window of surrounding points, using `rolling_aggregate` from Time-Stream. Points too close to either
  end of the dataset for a complete window are left null, as are windows holding too few values to meet the
  configured threshold. Supports `center`, `leading` and `trailing` alignment.
- **Point estimate aggregation**: `point_estimate` takes the nth value in each aggregation period as the
  aggregated value, for cases such as reporting a specific hourly value as the daily value.
- **Tipping bucket consolidation**: `get_precip_tipping` merges the `PRECIP_TIPPING_A` and `PRECIP_TIPPING_B` gauges
  into a single `PRECIP_TIPPING` dataset, taking the higher value where the two disagree.
- **`--sites` option for `list-sites`**: the fan-out helper can now be limited to a chosen set of sites. Listed sites
  are still checked against the network and the date window, and anything outside the network is dropped with a
  warning.
- **Derivation inputs with different periodicities**: `DerivationMethod.merge_inputs` is now an overridable step, so a
  derivation whose inputs do not share a periodicity can supply its own merge strategy. The deployment-attribute join
  has been split out into `join_deployment_attributes` so overrides can still use it. `get_snow_estimated_counts` uses
  this to broadcast daily snow values onto hourly counts.

### Bug fixes

- **Partial aggregation buckets at window edges**: processing now reads one day either side of the
  requested window via `extend_date_range`, so buckets sitting on the window boundary get all of their source data.
  The extra rows are trimmed off again before saving, so a run still only writes the days it was asked to process.
- **Corrections aligned by time**: `LWCorrection`, `PACorrection`, `WDCorrection` and `AlbedoSouthSlopeCorrection`
  now join their dependency datasets on the time column instead of relying on the rows lining up positionally. A
  dependency covering a different set of time values no longer shifts the corrected values.
- **QC dependency checks aligned by time**: a `dep_ts` quality-control check (e.g. against `BATTV`) runs against a
  different dataset that need not hold the same time values. The result is now joined back on time, with the checked
  dataset deciding which rows are kept.
- **Re-runs no longer keep stale values**: `merge_dataframes` now lets the incoming data decide the value of every
  column it holds, including where that value is null. A re-run can therefore remove a value it has decided is bad,
  and a flag column stays in step with the data column it describes.
- **Failed S3 reads no longer overwrite a day of data**: `ClientError` is the base class for every botocore error, so
  the writer was treating any read failure as "file not present" and replacing the stored day with only the rows from
  the current run. It now only treats `404` and `NoSuchKey` as a missing object, and re-raises everything else.
- **A missing column no longer fails a whole group**: the data query selects with `COLUMNS(c -> c IN (...))`, so a
  `source_column` absent from the parquet files is left out of the result rather than failing the query for every
  dataset in the group.
- **No sites selected raises an error**: `DatasetDependencyGraph` raises when no sites are active during the
  requested processing window, instead of continuing with an empty graph.
- **Empty processing plan raises an error**: a dataset with processing configs but no plan order now raises rather
  than being quietly skipped.
- **Non-zero exit on dataset failure**: dataset failures are still caught per dataset so one failure does not stop the
  rest of the run, but the run now raises at the end listing the failed datasets, so the exit code reflects it.
- **Deployment attribute lookup**: attributes are now fetched for the site and then filtered to the platform, rather
  than queried by platform ID, and a lookup that finds no matching attributes raises instead of returning nothing.
- **Exception tracebacks in local logs**: the local log formatter was dropping exception information; it now appends
  the `{exception}` field.
- **Time anchor constraint relaxed**: `merge_multiple_timeframes` no longer requires all inputs to share a time
  anchor. Anchors are handled at the metadata level and incompatible ones are not mixed within a network in practice.
  A check for compatible (rather than identical) anchors is still wanted here in future.

### Other changes

- `merge_multiple_timeframes` accepts a `join_type`, so callers can use a `"left"` join when the first input should
  decide which time values end up in the result.
- `DataProcessingConfig` carries a `site_id`, used by the deployment attribute lookup.
- Various package dependency updates

### Testing

- Added unit tests for the new derivation and aggregation methods, time-aligned corrections and QC checks,
  `merge_dataframes` precedence, `extend_date_range`, the writer's missing-object handling, the missing-column query
  path, and the new error cases for empty plans, no sites and failed datasets.
- Updated the end-to-end test data to match the widened read window and the corrected merge behaviour.
