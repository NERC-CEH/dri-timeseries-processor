## 0.2.0

First proper release on the new project scaffold. The repo has been migrated to the `pyservice`
[cookie cutter template](https://github.com/NERC-CEH/fdri-cookiecutter-templates), several new derivation operations are available, EddyPro post-processing is now
integrated end-to-end, and the versioning and release flow has been overhauled.

### New features

- **EddyPro post-processing pipeline** integrated into the timeseries processor.
- **New derivation operations:**
    - `calculate_vwc` (volumetric water content).
    - `correct_counts`.
    - `calc_factor_intensity`.
- **Load-only dependency handling**: datasets marked as load-only are skipped during processing but still
  resolved as dependencies.

### Project structure and tooling

- Migrated to the [`pyservice`](https://github.com/NERC-CEH/fdri-cookiecutter-templates) cookiecutter template.
- Replaced `autosemver` with a static `version` field in `pyproject.toml`. Patch bumps are now automated via a
  `pre-push` git hook (see below); minor and major bumps are manual via `make bump-minor` / `make bump-major`.
- New `Makefile` with targets such as: `bump-patch`, `bump-minor`, `bump-major`, `release`, `install-hooks`, `qa`,
  `docker-build`, `docker-run`.
- New `CHANGELOG/` directory: one file per release.

### CI/CD and release flow

- **`pre-push` git hook** (`.githooks/pre-push`): on every push to a feature branch, auto-bumps the patch component of
  `pyproject.toml` (and `uv.lock`) if the version line wasn't already changed. Install via `make install-hooks` after
  cloning.
- **`verify-version-bump` CI check**: any PR targeting `staging` whose head doesn't bump the version field is rejected.
  Catches pushes made without the hook installed and bot-created PRs (e.g. dependabot).
- **`release-ready` CI check**: PRs targeting `production` must bump the version *and* provide a populated
  `CHANGELOG/<version>.md` (no placeholder text, content beyond the heading).
- **Automated GitHub release** on every merge to `production`: tags the commit as `v<version>` and creates a release
  populated from `CHANGELOG/<version>.md`.
- **Auto-PR from `staging` to `production`** after each successful staging Docker deploy.
- New `pre-commit` git hook for `ruff format --check` and `ruff check`.
