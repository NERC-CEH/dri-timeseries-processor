# 0.11.0

Where datasets are read from and written to now comes from the distribution access URL in each dataset's metadata.
The processor no longer builds storage paths from the network, site, resolution and bucket; instead using the access URL
directly. This follows the repartitioning work carried out on our AWS S3 buckets.

The processor also moves to `time-stream` 4, and to new major versions of `duckdb` and `polars`.

### Main changes

- **Access URL instead of bucket and dataset**: `TimeSeriesContainer.distribution_url` is renamed to `access_url`.
  The `source_bucket` and `source_dataset` fields, and the `s3_bucket` and `s3_dataset_path` properties, are removed,
  and the `sourceBucket` and `sourceDataset` metadata fields are no longer
  read.
- **Datasets grouped by access URL**: loading and saving both group datasets by access URL, as datasets with the same
  URL are stored in the same files.
- **Storage client works on URLs**: every `StorageClient` method takes full URLs, and only `S3StorageClient` splits them
  into a bucket and key.
- **Readers and writer take URLs**: `RawFileReader.download` takes a `prefix_url`, and `ByteParquetWriter.write` takes
  the file's `url` in place of a bucket and key.

### Bug fixes

- **One bad group no longer stops saving**: a group of processed datasets with no access URL, or whose data can't be
  merged into one file (e.g. different resolutions), is marked as failed, and the other groups are still saved.
- **Missing access URL**: loading or staging raw files for a dataset with no access URL now raises a clear
  `ValueError`. When loading, the group is marked as failed.
- **Rolling aggregation on irregular data**: now raises a clear `ValueError` when the `TimeFrame` has no periodicity.

  `tenacity` 9.1.4 -> 9.2.1, `boto3` 1.43.108 -> 1.43.127.
