# 0.10.0

This release adds a `historic` mode, which processes everything for a network's sites over each site's full operating
dates. Date ranges longer than a year are now processed one calendar year at a time, whichever mode is used.

Loading data from S3 is faster, as DuckDB is now given the exact list of daily files to read rather than searching
the whole site.

This release also fixes a bug where core flags were not being set correctly (missing and removed wrongly being set
simultaneously).

### Breaking changes

- **Metrics job name per year**: when a run is split into calendar years, each year's metrics are pushed under the
  configured job name with `-<year>` added, so that one year doesn't overwrite another's. Runs of a year or less keep
  the plain job name.
- **Run fails at the end if any year failed**: a failed year or site no longer stops the rest of the run. All
  failures are reported once the run has finished, and the run then raises a `RuntimeError`.
- **`S3DataRouter` needs a storage client**: it now takes a `StorageClient` as a third argument, to list the files to
  read.
- **`update_quality_control_core_flags` no longer adds `removed`**: `QCPipeline.remove_flagged_data` now adds it, as
  that is the only point where a value removed by QC can be told apart from one that was already null.

### New features

- **`historic` mode**: `historic --network NETWORK [--sites SITE ...]` processes every dataset and periodicity for
  each site, from its start date in the metadata to its end date (or today, if still open), one calendar year at a
  time. A site with no start date is skipped and reported as a failure.
- **Yearly chunks**: a date range longer than a year is split into calendar years and run oldest first, each with its
  own dependency graph and processor, so less data is held in memory at once. Years in which none of the selected
  sites were open are skipped.
- **Start date moved to the first site opening**: for selections made by site (`from-selection`,
  `from-cross-product`), the start date is moved forward to when the earliest of the selected sites opened.
- **`SolarZenith` needs no input datasets**: the angle only depends on the time and latitude, so the method now builds
  its own time steps across the load window instead of borrowing them from `swin`.

### Bug fixes

- **`removed` and `missing` flags on the same value**: QC only adds the `removed` core flag to values that were
  present before QC removed them. A value that was already null, but flagged by a check such as `samples` or
  `manual_removal`, keeps just the `missing` flag.
- **Empty aggregation buckets**: a bucket with no source values at all is now flagged `missing` only, not `missing`
  and `removed`.
- **Sites from another network**: a site named with `--sites` or `--selection` whose metadata puts it in a different
  network from `--network` is now left out of processing runs, with a warning. Before, only `list-sites` did this. A
  site with no network in its metadata is now kept, including by `list-sites`.
- A derivation given no input datasets now raises a clear `ValueError` naming the method, unless it builds its own
  time steps like `SolarZenith`.

### Performance

- **Reading only the files needed**: the data router lists the site's daily `data.parquet` files in the date range
  and gives DuckDB that exact list, rather than a `**/date=*` pattern over the site's full history. The `date=`
  folders can sit directly under the site or one folder level below it (e.g. `serial_no=`).
- **One DuckDB connection per run**: `DuckDBParquetReader` reuses a single connection for every read, with
  `httpfs_connection_caching` turned on, and closes it when the run finishes.
- **`httpfs` installed in the Docker image**: the extension is installed at build time, so each pod doesn't download
  it on its first S3 query.
- This has increased speed of data loads by upto 35x (potentially more when measured in real runtime environments);
  speed increases are relative to the length of history for a given site.
