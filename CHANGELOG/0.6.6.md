# 0.6.6

Adds end-to-end test coverage for the EddyPro flux processing pipeline and bakes EddyPro into the main Docker image
instead of a separate `-eddypro` tag.

Adds structured JSON logging and relaxes a metadata validation constraint.

### Changes

- **EddyPro baked into main image**: The `EDDYPRO_IMAGE` build arg is now applied to
  the main staging and production images, removing the need for a separate `-eddypro`
  tagged variant.
- **JSON logging**: Introduces `setup_logging.py`, configuring the processor to emit
  structured JSON log records so Argo step output can be parsed automatically by the
  ECK logging stack, rather than requiring custom Fluentd parsing rules.
- **`HasCurrentValueItem` qualifier now optional (breaking metadata change)**: The
  `qualifier` field on `HasCurrentValueItem` annotations is no longer required,
  allowing metadata that omits it to validate successfully.

### Bug fixes

- **Time anchor propagation from bundles**: `LoadPipeline` now applies the target container's
  own `time_anchor` instead of inheriting it from the source bundle, fixing a crash in
  `merge_multiple_timeframes` for EddyPro output.
- **CLI date range validation**: `--start-date` and `--end-date` may now be equal, allowing a
  single day to be processed.

### Testing

- Added an end-to-end test for the flux processing pipeline at `flux-plynl`, with the EddyPro
  binary mocked.
- Added mock metadata API fixtures for flux.
